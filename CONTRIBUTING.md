# Contributing

OPP is a working draft. Engineering examples and precise interoperability failures are especially useful.

For a normative change, open an RFC using [the template](rfcs/0000-template.md). Describe the engineering problem, schema and prose changes, authority/state effects, examples, migration, and conformance evidence. Mark assumptions and unimplemented behavior clearly.

For an editorial or small corrective change, submit a pull request directly. Keep schemas, prose, example packages, and tests consistent. Run the commands in [the README](README.md) and regenerate example archives after payload changes.

Contributions are under the repository's Apache 2.0 license. By submitting work, you confirm that you have the rights to contribute it. Do not include customer or employee information, restricted standards text, or licensed third-party software without permission and attribution.

See [governance](docs/project/governance.md) for the proposed public decision process. Existing schema IDs and draft versions must not be silently repurposed after a published release.
