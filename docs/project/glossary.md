# Terminology

| Term | Meaning |
| --- | --- |
| Design | An immutable exchange snapshot of theoretical product definitions and requirements. |
| As-built | Recorded physical subjects and evidence referencing that exact snapshot. |
| Product definition | One part/assembly/kit/consumable identity at one exact revision. |
| State | The condition in which geometry or a requirement applies: finished, uncoated, restrained, flat, formed, etc. |
| Representation | Exact geometry, envelope, tessellation, or a derived presentation of a definition in a state. |
| Feature | An engineering subject such as a bore, pair of planes, or thread. |
| Region | A selected whole representation, set of entities, or exactly defined subregion. |
| Requirement | A typed normative engineering obligation on stated subjects in a stated condition. |
| Occurrence | One placement/use of a reusable child definition in a parent definition. |
| Occurrence path | Ordered occurrences from the package root to one actual use, including reused subassembly context. |
| Physical subject | One manufactured instance or explicitly bounded lot. |
| Observation | A measured/reported value or evidence about a physical subject and characteristic. |
| Evaluation | A reported comparison to a requirement and declared decision rule. |
| Disposition | Acceptance, rejection, pending action, or acceptance under an approved deviation. |
| FAIR | First Article Inspection Report; a structured accountability/evidence record, not automatic certification. |
| Semantic PMI | Computer-interpretable product and manufacturing information. |
| Graphic PMI | Visual annotations; their appearance alone does not establish machine-interpretable requirements. |
| AP242 | A STEP application protocol/information model, not merely a file extension. |
| Part 21 | A STEP serialization; its entity labels are local to the exact serialized payload. |
